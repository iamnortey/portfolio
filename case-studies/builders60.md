# Builders 60: the system behind a two-builder initiative

**Status:** public website and application workflow live. The programme has two places; completed participant projects and learning outcomes are still ahead.

[Public website](https://builders60.ninobyte.com/) · [Portfolio](../README.md)

## The problem

As the person running Ninobyte, I needed a dependable way to explain a build programme, accept applications, handle errors and support review. A page alone would not cover duplicate retries, interrupted submissions, consent choices or operational recovery.

## What I built

Using Codex and Claude Code as engineering partners, I built and released the programme website and application system. The work includes input validation, retry handling, application receipt recovery, separate assessment and publicity permissions, and a protected review workflow.

I also prepared operational monitoring, release verification and recovery instructions. Restore and capacity rehearsals used synthetic data in isolated environments. Real applicant records were not used for those tests.

## What changed

The programme now has a working public entry point and an application process with explicit success, failure and recovery states. I can build the programme around a tested operational foundation instead of asking applicants to navigate an improvised collection of messages and forms.

The 19 November 2026 release record reports **59 passing automated tests**, responsive checks at four widths and live desktop/mobile checks. These are engineering checks, not evidence of increased applications, commercial returns or participant success.

## The Codex learning direction

My next focus is helping **two builders use Codex to turn an idea into a working project**: define a useful problem, build a small version, test it with realistic examples, improve it and explain how to run it. The programme’s own application system gives me a concrete build to teach from.

This is a Ninobyte initiative. The Codex focus describes the intended tool and teaching workflow; it does not imply OpenAI sponsorship or a completed cohort.

## Why it matters to a small business

The same skills apply to customer intake, service requests, membership applications and staff review. The useful result is a clear process that handles mistakes and can be operated by a small team.

**My role:** product scope, design and copy decisions, AI-assisted implementation, review, verification and release decisions. I remain responsible for the finished system.
